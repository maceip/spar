Try it in 3 commands

Requires Python 3.11–3.14. spar demo starts a safe, local vulnerable target with synthetic users and proves real exploits against it in your terminal—no API keys needed. 

git clone https://github.com/maceip/spar
cd spar && pip install -e ".[dev]"
spar demo

What it breaks

Tool abuse

Tricking an AI into emailing another user's private invoice or issuing an unauthorized refund.

Shared memory poisoning

Planting hidden instructions in memory so a different user's later chat leaks data.

Hidden prompt injections

Sneaking commands inside shared documents, images, non-English messages, or connected tools.

False completions

Catching an AI that claims it deleted or updated a record when no tool ever ran.

One program, one loop

01 / RECON

Know the system first

Reads the codebase—or probes the live target for routes, tools, and permissions—to build a ranked, budgeted plan.

02 / ATTACK & PROVE

Models propose, code verifies

Runs N trials from fresh sessions. Nothing is reported until a deterministic oracle proves it and an independent critic fails to refute it.

03 / REPORT & REPLAY

Evidence, tests, and SARIF

Hands back a Markdown report, a failing pytest suite, and SARIF 2.1.0 output—then replays exact attacks after a patch lands.

How Spar talks about it

Target

The running application: an HTTP service, an API, or an interactive endpoint.

Objective

What an adversary wants to achieve—for example reading another user's private record or triggering an unauthorized action.

Attack

An autonomous mission pursuing that objective across multi-step exploits, access-control bypasses, and injections.

Proof

Hard evidence it worked: a planted canary seen, a side-effect logged, or a state change upheld by an independent critic.

Safety by default

Spar only contacts localhost and hosts explicitly allowlisted in spar.yaml, keeps state-changing actions disabled unless you opt in, and never writes account tokens or API keys into reports or generated tests.
